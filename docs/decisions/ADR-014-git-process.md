# ADR-014: Git-процесс — ветка на фазу, постепенные Conventional Commits

- **Статус:** Accepted · **Дата:** 2026-09-06

## Контекст
Проект разрабатывается coding-агентом автономно и долго; требуется прослеживаемая, ревьюопригодная история.

## Решение
1. Каждая фаза development-plan — отдельная ветка от актуального `main`
   (`phase/0-docs` … `phase/12-release`). Прямые коммиты в `main` запрещены, кроме первого `chore: init repository`.
2. Коммиты — по мере работы, по одному на логический этап (каталог → convention-плагины → экран → данные →
   тесты). WIP-коммиты запрещены; коммитить только зелёную сборку.
3. Сообщения — Conventional Commits в стиле skill `caveman-commit` (intent-only: `type(scope): summary`,
   тело только для неочевидного «почему», без AI-атрибуции и эмодзи). Scope = имя модуля
   (`feat(market):`, `feat(core):`), типы: docs/build/feat/test/fix/chore/ci/style.
4. Merge фазы в `main` — `git merge --no-ff` после DoD и зелёных assemble+test+detekt+lint.
   Следующая ветка — от обновлённого `main`.

## Альтернативы
- Один коммит на фазу — история не отражает этапы, ревью невозможно.
- Trunk-based без веток — для автономного агента рискованно (нет точки отката фазы).

## Последствия
- Каждое состояние `main` собирается и протестировано; откат фазы = revert merge-коммита.
