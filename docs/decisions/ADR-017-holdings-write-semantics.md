# ADR-017: Семантика записи холдингов (merge / replace / remove)

- **Статус:** Accepted · **Дата:** 2026-09-07

## Контекст
Phase 8 (Add/Edit Asset) требует однозначной семантики трёх операций `PortfolioRepository`.
ADR-013 зафиксировал локальное хранение портфеля и оставил заметку «повторное добавление того же
коина — merge, зафиксируем в Phase 8». В `development-plan` Phase 8 «Проверка» прямо требует
кейс «добавить тот же коин второй раз» и документирование поведения.

## Решение
1. `saveHolding(coinId, amount)` — **суммирует** с существующим холдингом (merge): повторное
   добавление того же коина из Coin Details складывает количества без предупреждения в UI.
2. `setHoldingAmount(coinId, amount)` — **заменяет** stored значение точным (Edit → Save Changes).
3. `removeHolding(coinId)` — удаляет запись (Edit → Remove Asset после подтверждения).
4. Нулевые и отрицательные количества отклоняются на уровне формы (`AssetAmountValidator`:
   непустой ввод, десятичная точка, строго больше нуля); репозиторий проверку не дублирует.
5. Цена коина может быть недоступна (коин вне кэша маркет-листа top-50 — ограничение Phase 7):
   Add-шит и Edit показывают прочерк «—» вместо Estimated Total Value, сохранение при этом
   разрешено — значение пересчитается, когда коин появится в кэше.

## Альтернативы
- `saveHolding` заменяет значение — повторное добавление теряло бы ранее введённое количество.
- Диалог/подтверждение при merge — усложнение формы, которого нет в макетах (aa507857/cf7756ee).

## Последствия
- UI Add-шита не показывает существующий холдинг (в макете поля нет) — пользователь узнаёт об
  объединении по итоговой сумме на Portfolio.
- Кейс «повторное добавление = сумма» проверяется на устройстве в Phase 8 (F2-цикл).
