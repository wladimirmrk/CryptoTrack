# ADR-002: Кросс-фичевые репозитории в :core:data

- **Статус:** Accepted · **Дата:** 2026-09-06

## Контекст
Данные рынка нужны всем фичам (market, coin-details, favorites, search, portfolio, assetentry). Если интерфейс
`MarketRepository` объявить в `feature/market/domain`, остальные фичи получат зависимость от feature-модуля —
запрещено правилами архитектуры.

## Решение
Общие репозитории — `MarketRepository`, `FavoritesRepository`, `PortfolioRepository`, `SettingsRepository` —
объявлены и реализованы в `:core:data` (интерфейс + impl в одном модуле, паттерн Now in Android).
Feature-модули зависят от `:core:data` и через Hilt получают интерфейсы. Фичевая логика (use cases) остаётся
в feature/domain и использует эти интерфейсы.

## Альтернативы
- Интерфейсы в каждой фиче + адаптеры — дублирование, ложные абстракции, риск расхождения.
- Отдельный `:core:domain` с интерфейсами и `:core:data` с реализациями — лишний модуль-прослойка при одном
  месте реализации; отказались в пользу единого `:core:data`.

## Последствия
- Нулевые feature→feature зависимости.
- Небольшой компромисс с «классикой» (интерфейс рядом с реализацией) — осознанно, компиляция Domain не зависит
  от реализаций, т.к. VM видит только интерфейс.
