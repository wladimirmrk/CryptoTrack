# Domain & Business Logic — CryptoTrack

Спецификация чистой бизнес-логики, алгоритмов расчёта портфеля и семантики изменения позиций.

---

## 1. Принципы слоя Domain

1. **Чистый Kotlin:** Слой `domain` не зависит от Android SDK (`androidx.*`, `Context` и т.д. запрещены правилами Konsist).
2. **Точность финансовых вычислений:** Все денежные величины и объёмы активов оперируют `BigDecimal` с контекстом `MathContext.DECIMAL32` для исключения ошибок округления чисел с плавающей точкой.
3. **Изоляция Use Cases:** Бизнес-логика оформлена в виде специализированных классов (`ObservePortfolioUseCase`, `PortfolioCalculator`), что обеспечивает 100% покрытие unit-тестами без моков Android фреймворка.

## 2. Расчёты портфеля (`PortfolioCalculator`)

Калькулятор принимает список пользовательских позиций `List<Holding>` и список актуальных котировок `List<Coin>`.

### 2.1 Стоимость позиции (Position Value)
Для каждого актива, найденного в котировках:
$$\text{valueUsd} = \text{currentPrice} \times \text{amount}$$
Если коин не найден в текущем кэше рынка, позиция временно пропускается в агрегатах (ограничение v1: расчёт только по закэшированным котировкам).

### 2.2 Общий баланс портфеля (Total Balance)
$$\text{TotalBalance} = \sum_{i=1}^{N} \text{valueUsd}_i$$

### 2.3 Изменение портфеля за 24 часа (24h PNL)
1. **Абсолютное изменение в USD:**
   $$\Delta_{24h} = \sum_{i=1}^{N} \left( \text{valueUsd}_i \times \frac{\text{priceChangePercentage24h}_i}{100} \right)$$
2. **Стоимость портфеля 24 часа назад:**
   $$\text{YesterdayValue} = \text{TotalBalance} - \Delta_{24h}$$
3. **Процентное изменение за 24 часа:**
   $$\text{ChangePercentage}_{24h} = \begin{cases} 
   \left( \frac{\Delta_{24h}}{\text{YesterdayValue}} \right) \times 100\%, & \text{если } \text{YesterdayValue} > 0 \\
   0.0\%, & \text{если } \text{YesterdayValue} \le 0 
   \end{cases}$$

### 2.4 Процент аллокации активов (Asset Allocation)
Для каждого актива в портфеле доля в донат-диаграмме вычисляется как:
$$\text{AllocationPercent}_i = \begin{cases} 
\left( \frac{\text{valueUsd}_i}{\text{TotalBalance}} \right) \times 100\%, & \text{если } \text{TotalBalance} > 0 \\
0.0\%, & \text{если } \text{TotalBalance} \le 0 
\end{cases}$$

## 3. Семантика записи холдингов (ADR-013 & ADR-017)

Пользователь управляет портфелем локально (без синхронизации с внешними биржами):

| Действие | Метод в `PortfolioRepository` | Поведение в БД |
|---|---|---|
| **Добавить актив (Add Asset)** | `saveHolding(coinId, amount)` | **Суммирование (Merge):** если коин уже есть в портфеле, новое количество прибавляется к текущему: `total = existing + amount` |
| **Редактировать актив (Edit Asset)** | `setHoldingAmount(coinId, amount)` | **Перезапись (Replace):** указанное количество полностью заменяет предыдущее значение |
| **Удалить актив (Remove Asset)** | `removeHolding(coinId)` | Запись о холдинге полностью удаляется из таблицы `holdings` |

### Валидация пользовательского ввода
- Поле `Amount` валидируется в представлении: допускаются только неотрицательные числа больше нуля (`amount > 0`).
- Запрещён ввод отрицательных чисел и нечисловых символов.
- В шите добавления актива выполняется live-расчёт:
  $$\text{Estimated Total Value} = \text{Amount} \times \text{CurrentPrice}$$

## 4. Форматирование финансовых значений (`:core:common`)

Для предотвращения визуального сдвига разрядов все числовые данные используют моноширинный шрифт **JetBrains Mono** (`label-numeric`):
- **Цены:** Форматируются с символом выбранной валюты (USD: `$`, EUR: `€`). Для криптовалют с ценой $< \$1$ используется расширенное число знаков после запятой (до 6 знаков).
- **Проценты:** Округляются до двух знаков после запятой, явно снабжаются знаком `+` при росте или `-` при падении.
